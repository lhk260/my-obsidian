# 论文与学习工作流

这套流程的目标不是“收藏更多”，而是让每次输入最终变成能解释、能复用、能输出的知识。

## 1. 捕获：只进一个入口

- 临时想法、网页线索、待读材料先放 `00-Inbox`。
- 论文统一先进入 Zotero；PDF、元数据和引用由 Zotero 管理。
- 在 Obsidian 中用命令面板运行 **Zotero Integration: Import Notes**，选择“论文精读”格式。

## 2. 筛选：三遍阅读法

### Pass 1（5–10 分钟）

只看标题、摘要、引言、结论、图表。回答：研究问题是什么、贡献是什么、与当前项目是否相关。低相关直接设为 `archived`。

### Pass 2（30–60 分钟）

沿“问题 → 假设 → 方法 → 证据 → 局限”建立模型。不要逐句翻译，优先理解关键图、关键公式和最强 baseline。

### Pass 3（真正重要的论文）

合上论文，凭记忆画方法流程、解释公式、预测失败条件，再回原文纠错。只有在这一步之后，笔记才算 `processed`。

## 3. 标注：证据和想法分开

- Zotero 负责原始 PDF 与高亮。
- Zotero Integration 把高亮导入文献笔记。
- PDF++ 用于在 Obsidian 内阅读时创建可回链的 PDF 证据。
- 高亮只表示“原文证据”；你自己的解释写在“我的综合”与“我的批注”中。

建议颜色语义：

- 黄色：定义 / 核心主张
- 红色：关键证据 / 结果
- 蓝色：方法 / 实现细节
- 紫色：疑问 / 局限 / 反例

## 4. 提炼：一篇论文不等于一个知识点

文献笔记保留“这篇论文说了什么”。可跨论文复用的机制、公式、经验或反例，使用 `Concept Note.md` 拆到 `30-Knowledge/Concepts`。概念笔记必须：

1. 用自己的话给出一句话解释；
2. 给一个最小例子；
3. 写明边界或反例；
4. 链回来源论文。

## 5. 复习：只复习值得长期保留的内容

- 要复习整篇笔记：将属性 `review` 改为 `true` 并添加 `#review`。
- 要复习具体知识：用 `Q:: A::` 写主动回忆卡片，并给该笔记添加 `#flashcards`。
- 每天先回忆再翻答案；每周在周记中检查“仍然解释不清的问题”。
- 不要把所有摘录做成卡片；卡片只覆盖定义、关键机制、易混淆对比和高价值公式。

## 6. 输出：用项目验证知识

每篇精读笔记至少产生一种输出：

- 一个概念笔记；
- 一个复现实验；
- 一段 related work；
- 一个研究问题或可证伪假设；
- 一次组会讲解。

## 最小日常动作

1. 清空 `00-Inbox`；
2. 处理一篇论文的一个 Pass；
3. 做到期复习；
4. 把一个知识点讲清楚或用于项目。

## 文件夹含义

- `00-Inbox`：未处理输入
- `10-Daily`：日记与周复盘
- `20-Literature`：论文、PDF、阅读队列与旧笔记
- `30-Knowledge`：概念、技能、工具和知识地图
- `40-Courses`：课程材料
- `50-Projects`：有明确结果与结束条件的项目
- `60-Outputs`：文章、分享、想法成稿
- `80-Imports`：外部平台导入
- `90-System`：模板、脚本、附件和指南
- `99-Archive`：完成或不再活跃的内容
